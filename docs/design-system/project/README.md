# Beyond Service — Design System and Content Library

A single source for the Beyond Service corporate website redesign. Everything an engineer, writer or designer needs to ship consistent work lives here: the brand book, every design token, the full copy for every page, the vendor registration flow, FAQs, team context, verification register, and the 3D and motion direction. There is no second document.

**Company.** Beyond Service is a Surat-headquartered B2B Integrated Facility Management and project execution organisation. The business operates across 14+ states in India and partners with 500+ vetted service providers to serve 100+ corporate clients across nine verticals.

**Scope of this system.** It covers brand identity, visual design tokens, typographic system, motion and 3D direction, and the complete copy library for the public website: homepage, About, nine service detail pages, vendor registration, team, and contact.

---

## Visual direction in one paragraph

Charcoal and cream dominate. Champagne is the single accent. The site reads like a corporate monograph: generous whitespace, intentional headline wrapping, architectural photography, precise type and restraint on effects. The 3D element is a signature, not a stunt. No navy, no safety-amber from the current site, no blue-purple gradients, no glass-morphism, no neon glow. The audit palette in `assets/Beyond_Service_UIUX_Audit_and_Website_Prompt.pdf` documents the existing navy/amber brand; this system supersedes it.

## How to read this system

Read in order.

1. **`project/README.md`** — this file. Context and index.
2. **`project/tokens.json`** — colour, type, spacing, radius, shadow, opacity, blur and z-index tokens. Every value is final.
3. **`project/01-brand-foundations.md`** — voice, principles, naming, do and don't.
4. **`project/02-information-architecture.md`** — site map, URLs, nav behaviour.
5. **Page content, `03` through `16`** — complete copy for every public page, section by section. Use these as the single source of truth for every string on the site.
6. **`project/17-components-and-patterns.md`** — component inventory with props, variants and anatomy.
7. **`project/18-motion-and-3d-direction.md`** — motion vocabulary, 3D scene concept, performance budget, reduced-motion fallbacks.
8. **`project/19-team.md`** — current state of team content and what still needs verification.
9. **`project/20-implementation-and-verification.md`** — stack choices, QA checklist, verification register, open questions.
